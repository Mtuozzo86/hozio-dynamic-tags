== Version 4.12.13 (June 2026) ==

= New Features =

* Lead Submissions: Fluent Forms submissions are now captured automatically,
  joining the existing Elementor, WPForms, Gravity Forms, Contact Form 7, and
  Divi integrations. Name, email, and phone are auto-detected (by field name or
  label), composite name/address fields are handled, and entries appear in the
  Lead Submissions dashboard with the Fluent Forms badge and in the platform
  filter dropdown.

== Version 4.12.12 (June 2026) ==

= Improvements =

* Image sitemap: orphaned media library images (uploaded to a post's editor but
  never inserted into content) are now excluded. Only images actually present in
  published page/post content appear in image.xml — detected via wp-image-{id}
  class in classic editor content, gallery shortcodes, featured images, Elementor
  widget data, and Gutenberg blocks.

* Video sitemap: video.xml is no longer listed in sitemap_index.xml when the site
  has no videos referenced in published content, preventing Google from crawling
  an empty file. The entry reappears automatically once a video is placed on a
  published page.

* Video sitemap: the video sitemap setting is now auto-enabled the first time any
  video file is uploaded to the media library, so clients do not need to manually
  toggle the setting.

== Version 4.12.6 (May 2026) ==

= Fixes =

* Fix: Elementor Icon List widget — strip raw <u> / </u> tags typed directly
  into text fields. Validators flagged these as "tag must be paired" /
  "start tag match failed". Uses Elementor's render_content filter so only
  Icon List output is affected; CSS underline styles are untouched.

* Fix: Remove <link> tags with empty or missing href from wp_head output.
  W3C error: "The attribute href of the tag link must have a value." Handled
  inside the existing full-page output buffer (no extra ob_start needed).
  Catches both href="" / href='' and bare href with no value.

* Fix: Escape genuinely stray < and > characters in post content. Converts
  bare angle brackets that are not part of a valid HTML tag to &lt; / &gt;.
  Applied via the_content filter at priority 20. Conservative regexes avoid
  touching normal markup, shortcodes, scripts, or style blocks.

== Version 4.12.5 (May 2026) ==

= Improvements =

* Improvement: Consolidated all HTML output fixes into a single unified output
  buffer (ob_start at priority 0). Previously the cta-text-color deduplication
  ran in its own buffer at priority 10; it now shares one pass with the new
  universal fixer, reducing overhead on every front-end page load.

* New: Universal HTML Validation Fixer — four server-side fixes applied to
  front-end HTML before delivery:
    A. Duplicate id="cta-text-color" deduplication (existing, now merged in)
    B. Inline <script> CDATA wrapping — validators that check XHTML rules flag
       bare & / < / > in JS blocks; wrapping with //<![CDATA[ ... //]]> silences
       this. JSON-LD (application/ld+json) and non-JS script types are explicitly
       excluded to protect structured data.
    C. Nav menu <ul>/<li> line normalisation — Elementor concatenates list items
       onto one line; validators lose the parent <ul> context. Newlines restore
       correct nesting visibility.
    D. Elementor lightbox attribute entity cleanup — captions with special
       characters get double-encoded (&quot; etc.) inside data-elementor-lightbox-
       title / -description attributes. Decoded and re-encoded cleanly.
  All fixes are gated on fast strpos() checks so pages without the pattern are
  untouched. Skipped on admin, AJAX, REST, WP-CLI, and feed requests.

== Version 4.12.4 (May 2026) ==

= Fixes =

* Fix: Duplicate id="cta-text-color" HTML validation errors on pages that use
  Elementor Loop widgets. Each Loop iteration rendered the same template,
  producing multiple elements with the same ID. Fixed via server-side output
  buffering (ob_start on template_redirect): the first occurrence is kept as
  an ID, all subsequent ones are rewritten to class="cta-text-color". CSS and
  JS updated to target both selectors so the visual behavior is unchanged.
  No template edits required — fix applies to all existing sites automatically.

* Fix: XML processing instruction prefix leaking into rendered page HTML on
  HOG/town pages that use the "hide-if-empty-acf" or "hide-if-no-wiki"
  widget classes. The prefix was injected before DOMDocument::loadHTML()
  to force UTF-8 parsing, but PHP's saveHTML() doesn't reliably strip it
  back out (especially with LIBXML_HTML_NOIMPLIED), causing browser
  warnings, HTML validator errors, and rendering issues in strict modes.
  Now explicitly stripped from the returned content.

== Version 4.12.3 (May 2026) ==

= New Features =

* NEW: Search-replace protection for all Hozio Pro settings — every editable
  field on the Dynamic Tags Settings page is stored base64-encoded in
  wp_options ("b64:" prefix for strings, "b64arr:" for arrays). Site-wide
  search/replace tools (Better Search Replace, WP-CLI search-replace, host
  migration tools, etc.) can no longer match the values and accidentally
  mangle them. Reads are decoded transparently — Elementor dynamic tags,
  shortcodes, admin display, and any get_option() consumer always see plain
  text. Protected fields: phones, emails, address parts, business hours
  (HTML and Classic structures), URLs, colors, and custom dynamic tags.
  One-time auto-migration encodes existing plain-text values on first
  admin page load.

* NEW: Email validation on Contact Form Email(s) — rejects malformed
  addresses on save with a prominent red banner pointing at the bad
  values. Comma-separated lists (e.g. "support@hozio.com, sales@hozio.com")
  remain valid. Client-side check on submit blocks bad input instantly;
  server-side check is a safety net.

= Trade-off =

* Domain migrations that update URLs via search/replace will NOT update
  URLs stored in the protected fields. After such a migration, re-save the
  Dynamic Tags Settings page once.
